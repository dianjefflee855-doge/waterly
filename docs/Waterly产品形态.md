# Waterly 产品形态

Waterly 是开源（MIT）、自部署的多平台、多账号智能沟通助手（首个场景为微信自动回复助手）。它通过读屏与系统通知获取消息，由 AI 起草回复、翻译与汇总，但**每一条发出去的消息都由用户亲自确认**。产品 Mac 优先，采用 Electron 客户端，大模型使用 MiniMax。

> **开源模式（2026-10 起）**：不再规划中心化服务端、账号登录与防破解；安全依靠自部署 + 端到端加密，所有设置与密钥只保存在用户自己的 Mac 上。

本文依据已确认的 12 点产品规划整理，分为五个部分；标注「待实现」的条目为已确定方向、尚未开发的内容。

## 一、产品定位与目标用户

1. **产品定位**
   - 产品名 Waterly，开源的微信（及多聊天应用）自动回复助手，MIT 许可，代码全部公开在 GitHub。
   - 全开源、自部署：没有官方服务器；大模型 Key（MiniMax 或任意 OpenAI 兼容接口）、中继服务器和手机网页端都由用户自己提供和部署。
   - Mac 优先，蓝色水滴品牌形象。
   - Mac 端交互：关闭窗口只隐藏窗口，Dock 图标保留；按 Cmd+Q 才真正退出。（已实现）

2. **目标用户**
   - 做国外生意、同时经营多平台多账号的外贸销售人员。
   - 不擅长社交的人群，例如不知道如何与异性、长辈、同事沟通的人。
   - 适用的关系类型不限于商务。

## 二、消息获取

3. **消息抓取**
   - 视觉识别（读屏 / OCR）与系统通知两路并行。视觉方案不挑平台，屏幕上显示的内容都能获取。
   - 有网页入口的平台（Telegram、Instagram、Facebook、X 等）也可读取网页版 DOM。（待实现）
   - 不读取聊天应用的本地数据库、文件或内存，不做破解或注入。
   - 当前状态：通知横幅监听、截图 / OCR 与辅助功能（AX）读取已实现；微信、WhatsApp、Telegram 适配器已实现，QQ、企业微信仅有配置桩（待实现）；自建 YOLO 检测尚未接入（待实现）；微信群聊发送者识别待实现。

4. **聚合聊天客户端**（待实现）
   - 跨平台（Android / iOS / Mac / Windows）统一入口，按平台分组。
   - 每个平台显示新消息数，点进去查看明细。
   - 账号可登录在任意设备（包括服务器），Waterly 装在哪台设备，会话就在哪台设备。
   - 在任意设备打开聚合客户端都能查看消息。

## 三、AI 能力

5. **AI 简报 / 提醒**（待实现）
   - 每三小时定时汇总一次。
   - 列出用户承诺过的事（如「Jeff 明天出方案、订三十套」）、被 @ 的消息和待跟进事项。
   - 能从「好的」这类回复中识别出承诺。

6. **自动回复**
   - 自动回复**默认关闭**；即使开启，也只生成草稿，每一条发出的消息都必须经用户批准。（已实现）
   - 知识库 + 规则：命中时使用标准答案。（待实现）
   - 大模型兜底：未命中时由大模型根据聊天上下文生成回复。（草稿生成已实现）
   - 多语言覆盖：中东、欧洲、东南亚、日韩等。

7. **辅助回复**
   - 双向实时翻译（如阿拉伯文 ↔ 中文）。（待实现）
   - AI 基于聊天上下文起草回复选项，用户选定并确认后才发送。
   - 微信 / WhatsApp 个人号的发送方式：默认「复制到剪贴板」，由用户自行粘贴发送；「自动输入」为可选项，开启时须提示风险。（发送模式设置待实现）
   - Telegram 计划改用官方 Business Bot。（待实现）

8. **身份识别与提示词系统**（待实现）
   - 对方可以是客户、恋人、异性、长辈、同事等。
   - 每种关系一套身份档案和提示词。
   - AI 先判断对方身份，再套用对应的回复风格。

## 四、架构与安全

9. **核心架构**
   - Electron 客户端 + 可选的自建视觉识别（YOLO / OCR）+ MiniMax 大模型（OpenAI 兼容接口）。
   - 自带 Key（BYO key）：首次启动时填写自己的 API Key，服务商可选 MiniMax 或任意 OpenAI 兼容接口（自填 Base URL 与模型）。（已实现）
   - Key 只保存在本机 `~/.config/waterly/config.json`（权限 0600），只在主进程使用，不进安装包、不进仓库、不经过任何中继。
   - 安装包与源码一律按「已公开」对待，不含任何密钥。

10. **自部署**（已实现）
    - 中继服务器：每个用户部署到自己的 Cloudflare 账号（`relay/README.md`），注册密钥可选、由用户自己设置。
    - 手机网页端：部署到自己的域名或 GitHub Pages，中继地址可在页面或 `<meta name="waterly-relay">` 中配置。
    - 原「防破解」与「联网登录」规划随开源决定作废。

11. **签名与分发**（待实现）
    - 目前为 ad-hoc 签名，用户自行从源码构建；后续可由社区提供签名公证的 Release。

## 五、合规边界

12. **合规边界**
    - AI 只辅助，发送由用户决定。
    - 不冒充、不操纵。
    - 不读取聊天应用的本地数据库，不破解、不注入，不复制其他产品的代码、提示词或品牌。

> 说明：仓库中的 `native/mac/grokcall` 是可选的语音唤醒小工具（唤醒词触发某个桌面 AI 助手的语音通话），不属于 Waterly 核心功能，需自行配置目标链接。

## 当前进度与待办

**当前进度（MVP 阶段）**
- Electron 控制面板：应用列表、权限状态、消息流、草稿审批、自动回复总开关。
- 通知横幅监听（ncwatch）+ 截图 / OCR / AX 读取聊天上下文；微信、WhatsApp、Telegram 适配器。
- 自带 Key 起草回复（MiniMax / OpenAI 兼容接口，自动剔除推理内容）；发送方式（复制到剪贴板默认 / 自动输入可选）；远程访问（自部署中继 + 端到端加密）；所有发送须经用户确认；自动回复默认关闭。
- 微信发送已接通（粘贴发送，发送前严格校验焦点）。
- Mac 窗口行为：关闭即隐藏、Dock 保留、Cmd+Q 退出。

- 签名公证的 Release 包。
- Telegram 改用官方 Business Bot。
- AI 简报、知识库与规则、双向翻译、身份识别与提示词系统。
- 聚合聊天客户端、网页版 DOM 读取、QQ / 企业微信适配、YOLO 检测、微信群聊发送者识别。
